# 安全运行 Pi

将模型生成的命令和代码视为不可信。Pi 能够以启动它的账户权限读取、修改和执行文件，并且不会在每次调用工具前征求批准。扩展、软件包安装程序、语言服务器及其他子进程也以相同权限运行，除非操作系统或虚拟化边界对它们加以限制。

文件、评论、指令、命令输出及模型响应都可能通过提示词注入来引导模型。项目信任机制控制着启动时加载哪些项目资源，但并不能使这些内容或由此产生的操作变得安全。

安全来自于限制 Pi 在生成的行动错误或恶意时所能访问和影响的文件、凭据、进程及网络服务。查看会话记录、使用项目信任机制以及审查更改并不能建立安全边界。

## 选择如何运行 Pi

运行 Pi 的不同方式会对生成的命令所能访问的内容施加不同限制：

| Pi 的运行方式 | 仍受保护的内容 |
|---|---|
| 直接以操作系统用户的权限运行 | 该用户无法访问的任何内容。专用用户账户可以缩小这些权限，但 Pi 仍与其他用户共享操作系统和网络。 |
| 完全在容器、虚拟机或沙箱内运行 | 您未暴露给环境的主机文件和进程。如果您在环境内提供凭据和网络服务，它们仍然可访问。这通常是实际中最强的选项。 |
| 在隔离环境外部运行，仅其内置工具在内部运行 | 主机资源受到保护，免受通过这些工具执行的操作影响。Pi 本身和其他扩展仍位于边界之外，因此这是一种较窄的隔离形式。 |

工作文件夹控制资源发现和工具的默认位置，但它不会阻止命令访问 Pi 进程可用的其他路径。

无论您选择哪种选项，仅提供任务所需的文件和服务。尽可能将凭据保留在环境之外，或使用范围狭窄、短期有效的凭据。当命令不需要网络访问时，限制网络访问。

有关设置说明和每种隔离方法的限制，请参阅[在隔离环境中运行 Pi](/docs/containerization/)。

## 了解项目信任

项目信任控制 Pi 是否加载工作文件夹提供的大部分设置和资源。它防止文件夹在你批准之前静默加载可执行扩展。

项目信任并非完整的启动边界。Pi 在选择或创建会话时，会在解析项目信任之前读取项目的 `sessionDir` 设置。拒绝信任会阻止其余项目设置和受保护资源加载，但无法撤销最初的会话目录查找。

项目信任不限制工具调用可以访问或影响的内容。Pi 启动后，启用的工具仍使用 Pi 进程的操作系统权限。文件夹中的指令和其他内容也可能影响模型。

### 受项目信任保护的资源

当 Pi 从当前工作目录中发现以下任一资源时，需要做出项目信任决策：

- `.pi/settings.json`
- `.pi/mcp.json`
- `.pi/extensions`、`.pi/skills`、`.pi/prompts` 或 `.pi/themes`
- `.pi/SYSTEM.md` 或 `.pi/APPEND_SYSTEM.md`
- 当前目录或上级目录中的项目 `.agents/skills`

仅包含 `.pi` 目录本身并不需要项目信任。

授予项目信任后，Pi 可以加载：

- 项目设置
- 来自 `.pi/mcp.json` 的项目 MCP 服务器
- `.pi` 下的扩展、技能、提示词模板、主题和系统提示词文件
- 通过项目设置配置的缺失软件包
- 项目本地及项目软件包扩展

拒绝项目信任将跳过这些受保护的资源，但上述初始 `sessionDir` 查找除外。

上下文文件（如 `AGENTS.override.md`、`AGENTS.md` 和 `CLAUDE.md`）的加载不受项目信任影响，除非你禁用上下文加载。即使你拒绝项目信任，也应将文件夹中的指令视为不可信输入。

### Pi 如何选择信任决策

命令行 `--approve` 或 `--no-approve` 覆盖优先适用。当存在受保护资源且没有命令行覆盖时：

1. 用户级和命令行扩展可以处理 `project_trust` 事件。首个返回“是”或“否”的扩展拥有决策权。
2. 若没有扩展做出决定，Pi 会查找当前目录或其父目录中已保存的决策，采用最近的一条。
3. 若没有适用的已保存决策，Pi 则遵循全局 `defaultProjectTrust` 设置，其默认值为 `"ask"`。

已保存的决策使用规范目录路径，存放于：

```text
~/.pi/agent/trust.json
```

使用 `/trust` 为未来的 Pi 进程保存决策。

### 无需交互式提示的项目信任机制

打印模式、JSON 模式及 RPC 模式无法展示内置的信任提示框。若未通过命令行覆盖、扩展或已保存的选择进行设置，则适用以下规则：

- `defaultProjectTrust: "always"` 将加载受保护的项目资源。
- `defaultProjectTrust: "ask"` 或 `"never"` 则会跳过这些资源。

当自动化运行需要明确的一次性决策时，请使用 `--approve` 或 `--no-approve` 参数。

## 减少影响并改善恢复

这些实践并不能替代隔离，但能减少暴露或使恢复更加容易：

- 仅授予 Pi 完成任务所需的文件和服务的访问权限。
- 在进行重大更改前，使用快照、备份或版本控制。
- 在加载扩展和软件包前进行审查。扩展在 Pi 进程内执行。
- 优先使用范围狭窄、短期有效的凭证。
- 在将结果应用到其他系统前，审查差异和生成的输出。
- 在导出或分享会话前进行审查。它们可能包含提示词、工具参数、命令输出、文件内容以及对话期间暴露的凭证。

## 报告安全问题

请遵循仓库的[安全政策](https://github.com/earendil-works/pi/blob/main/SECURITY.md)。对于涉及安全敏感的报告，请勿公开提交问题。

本地代理的预期行为、来自不可信内容的提示注入、缺乏内置沙箱，以及用户安装的扩展或技能所引发的行为，通常不在安全边界之内，除非报告能证明存在权限边界绕过或本地用户原本不具备的访问权限。
