# 会话

Pi 将会话保存为对话记录，方便您继续工作、从早期的轮次中分支探索，以及回顾之前的路径。

## 会话存储

会话自动保存至 `~/.pi/agent/sessions/`，按工作目录组织。每个会话是一个 JSONL 文件，采用树形结构。

```bash
pi -c                  # 继续最近的会话
pi -r                  # 浏览并选择过去的会话
pi --no-session        # 临时模式；不保存
pi --name "my task"    # 启动时设置会话显示名称
pi --session <path|id> # 使用特定的会话文件或部分会话 ID
pi --fork <path|id>    # 将会话文件或部分会话 ID 分叉为新会话
```

在交互模式中使用 `/session` 查看当前会话文件、会话 ID、消息数量、令牌和成本。

关于 JSONL 文件格式和 SessionManager API，请参阅 [会话格式](/docs/session-format/)。

## 会话命令

| 命令 | 描述 |
|---------|-------------|
| `/resume` | 浏览并选择之前的会话 |
| `/new` | 开启新会话 |
| `/name <名称>` | 设置当前会话的显示名称 |
| `/session` | 显示会话信息 |
| `/tree` | 导航当前会话的树状结构 |
| `/fork` | 基于之前的一条用户消息创建新会话 |
| `/clone` | 将当前活动分支复制到新会话中 |
| `/compact [提示词]` | 总结较早的上下文；参见[压缩](/docs/compaction/) |
| `/export [文件]` | 将会话导出为HTML |
| `/share` | 以私有GitHub gist形式上传，生成可共享的HTML链接 |
| `/bug [描述]` | 向Pi开发者报告缺陷；参见[报告缺陷](#reporting-bugs) |

## 恢复和删除会话

`/resume` 为当前项目打开交互式会话选择器。`pi -r` 在启动时打开相同的选择器。

在选择器中，您可以：

- 通过输入进行搜索
- 使用 Ctrl+P 切换路径显示
- 使用 Ctrl+S 切换排序模式
- 使用 Ctrl+N 筛选到已命名会话
- 使用 Ctrl+R 重命名
- 使用 Ctrl+D 删除，然后确认

当可用时，pi 使用 `trash` 命令行工具进行删除，而不是永久移除文件。

## 命名会话

使用 `/name <name>` 为会话设置一个人类可读的名称：

```text
/name Refactor auth module
```

在启动时使用 `--name` 或 `-n` 设置名称：

```bash
pi --name "Refactor auth module"
pi --name "CI audit" -p "Review this build failure"
```

命名会话在 `/resume` 和 `pi -r` 中更容易找到。

## 使用 `/tree` 进行分支

会话以树形结构存储。每个条目都有 `id` 和 `parentId`，当前位置是活动叶子节点。`/tree` 允许你跳转到之前的任意节点，并从此处继续，无需创建新文件。

<p align="center"><img src="images/tree-view.png" alt="树形视图" width="600"></p>

示例结构：

```text
├─ user: "你好，你能帮忙..."
│  └─ assistant: "当然可以！我能..."
│     ├─ user: "让我们试试方法A..."
│     │  └─ assistant: "对于方法A..."
│     │     └─ user: "这成功了..."  ← 活动节点
│     └─ user: "实际上，方法B..."
│        └─ assistant: "对于方法B..."
```

### 树形控件

| 按键 | 操作 |
|-----|--------|
| ↑/↓ | 导航可见条目 |
| ←/→ | 向前/向后翻页 |
| Ctrl+←/Ctrl+→ 或 Alt+←/Alt+→ | 折叠/展开或在分支段之间跳转 |
| Shift+L | 在所选条目上设置或清除标签 |
| Shift+T | 切换标签时间戳 |
| Enter | 选择条目 |
| Escape/Ctrl+C | 取消 |
| Ctrl+O | 循环切换过滤模式 |

过滤模式包括：默认、无工具、仅用户、仅标签化和全部。可通过 [设置](/docs/settings/) 中的 `treeFilterMode` 配置默认模式。

### 选择行为

选择用户消息或自定义消息：

1. 将叶子节点移动到所选消息的父级。
2. 将所选消息的文本放入编辑器。
3. 允许您编辑并重新提交，从而创建新分支。

选择助手、工具、压缩或其他非用户条目：

1. 将叶子节点移动到该条目。
2. 将编辑器留空。
3. 允许您从该点继续。

选择根用户消息会将叶子节点重置为空对话，并将原始提示词放入编辑器。

## `/tree`、`/fork` 和 `/clone`

| 功能 | `/tree` | `/fork` | `/clone` |
|------|---------|---------|----------|
| 输出 | 同一会话文件 | 新会话文件 | 新会话文件 |
| 视图 | 完整树状图 | 用户消息选择器 | 当前活动分支 |
| 典型用途 | 就地探索备选方案 | 从较早的提示词开始新会话 | 在继续前复制当前工作 |
| 概要 | 可选分支概要 | 无 | 无 |

当你想将备选方案保留在一起时，使用 `/tree`。当你想要单独的会话文件时，使用 `/fork` 或 `/clone`。

## 分支摘要

当 `/tree` 从一个分支切换到另一个分支时，pi 可以总结被放弃的分支，并将该摘要附加到新位置。这保留了您离开路径的重要上下文，而无需重放整个分支。

提示时，请选择以下之一：

1. 不生成摘要
2. 使用默认提示词生成摘要
3. 使用自定义焦点指令生成摘要

有关分支摘要的内部机制和扩展钩子，请参阅 [压缩](/docs/compaction/)。

## 报告 Bug

`/bug [description]` 为 Pi 开发者收集错误报告。该报告不会公开共享。对话框要求提供可选的描述，并询问是否包含会话记录。如果你拒绝提供会话记录，pi 会建议由当前模型编写一份出错摘要；会话记录将随你的凭证发送给你的提供商，只有摘要被附带。

最后一步选择报告的发送位置：

- **上传报告** 通过 `radius.pi.dev` 发送给 Pi 开发者。无需登录；如果你已登录 Radius，报告将归属于你的账户，以便开发者跟进。如果上传失败，pi 会建议改为导出 zip 文件。
- **导出为 Zip** 将 zip 归档写入当前目录。请将其附加到问题（issue）中或自行发送给开发者。

两者包含相同的文件：

| 文件 | 内容 |
|------|------|
| `report.json` | pi 版本、运行时、操作系统、终端、当前模型和提供商配置、已加载的扩展以及设置。API 密钥、标头值、URL 凭证和分析跟踪 ID 绝不会包含在内。 |
| `diagnostics.json` | 提供商和运行时错误诊断，附着于整个会话中的助手消息（失败或中止的轮次、重试、错误消息），以及任何记录的崩溃。始终包含；不包含消息内容。 |
| `session.jsonl` | 会话的当前分支，仅在你选择包含时出现。它包含会话期间读取的文件内容和命令输出。 |
| `summary.md` | 模型编写的摘要，仅在你选择生成时出现。 |

每个报告都有一个 UUID。pi 在上传或导出后显示它，并将其记录在会话中作为 `pi.bug-report` 条目，以便你之后引用。

设置 `PI_RADIUS_GATEWAY` 以上传到不同的 Radius 部署。

### 崩溃

当 pi 因未捕获的异常或致命运行时错误而退出时，它会将错误消息和堆栈跟踪存储在 `~/.pi/agent/crashes.json`（最新的五个）。下一次交互式启动时会显示一次警告；运行 `/bug` 会将存储的崩溃附加到 `diagnostics.json`，并在报告上传或导出后移除该文件。如果你希望在报告中包含转录内容，请先用 `pi -r` 恢复崩溃的会话。

## 会话格式

会话文件为 JSONL 格式，包含消息条目、模型变更、思考级别变更、标签、压缩、分支摘要以及扩展条目。

关于解析器、扩展、SDK 使用及完整的 SessionManager API，请参阅[会话格式](/docs/session-format/)。
