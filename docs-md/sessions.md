# 会话和上下文

Pi 将对话保存为会话。该会话的活动分支为下一个模型请求提供对话历史。使用会话命令以继续工作、探索另一个分支或减少发送给模型的历史量。

## 继续或切换会话

Pi 会自动保存会话，除非你使用 `--no-session` 启动它。

```bash
pi --continue
pi --resume
```

`--continue` 打开当前工作目录最近的会话。`--resume` 打开会话选择器。在交互模式下，`/resume` 打开相同的选择器，`/new` 则开始新会话。

使用 `/name` 或 `--name` 为会话指定一个易识别的名称。运行 `/session` 可查看当前会话文件、ID、消息数量、令牌使用量和成本。

会话选择器允许你搜索、重命名和删除会话。它还可以显示路径、更改排序，并将结果限制为已命名的会话。有关其快捷键，请参阅 [键绑定](keybindings.md#sessions)。

## 选择分支方式

Pi 将条目存储为树状结构，因此返回较早的节点不会抹去你所离开的分支。

| 操作 | 结果 | 适用场景 |
|---|---|---|
| `/tree` | 在当前会话文件内移动 | 相关的备选方案应保持在一起 |
| `/fork` | 从较早的用户消息创建新会话 | 备选方案应成为独立的工作 |
| `/clone` | 将当前活动分支复制到新会话 | 希望获得当前状态的独立副本 |

在 `/tree` 中，选择一条用户消息可将其文本放回编辑器。编辑并提交以创建另一分支。选择助手回复或其他条目，则会在该条目后以空编辑器继续。

当你离开一个分支时，Pi 可以对其进行总结，并将该总结附加到你进入的分支上。这样可以保留所放弃路径中的相关成果，而无需包含其中的全部消息。

关于持久化树形结构和条目类型，请参阅[会话格式](/docs/session-format/)。

## 管理会话上下文

模型接收的是活跃分支，而非会话文件中的全部分支。Pi 会将该历史与系统提示词、发现的上下文文件、可用工具以及加载的技能描述相结合。 [Pi 的工作原理](how-pi-works.md#context) 描述了这些输入是如何整合的。

页面底部显示了当前的上下文使用情况。当活跃上下文接近模型限制时，Pi 通常会自动压缩较早的历史记录。压缩操作会添加一份摘要并保留最近的消息，但不会删除原始的会话条目。

运行 `/compact` 可手动进行压缩。当摘要需要保留特定主题或决策时，您可以添加相应指令。可通过 [设置](settings.md#compaction) 来配置自动压缩及保留的历史记录。

如果提供商不可用或无法接受摘要请求，压缩可能会失败。请解决提供商问题后再次运行 `/compact`。禁用自动压缩并不会禁用手动命令。

请参阅 [压缩参考](/docs/compaction/) 了解阈值、保留边界、分支摘要行为及扩展挂钩。

## 控制会话存储

默认情况下，Pi 将会话存储在 `~/.pi/agent/sessions/` 目录下，并按工作目录分组。可使用 `--session-dir`、`PI_CODING_AGENT_SESSION_DIR` 或 `sessionDir` 设置来指定其他位置。其中命令行选项优先级最高。

使用 `--no-session` 进行临时运行。临时会话在 Pi 退出后无法恢复。

当已知会话路径或 ID 时，使用 `--session`。在交互模式启动前，可使用 `--fork` 从现有会话创建新会话。

## 导出或分享会话

使用 `/export` 将当前会话写为 HTML 或 JSONL。使用 `/share` 上传它并获取查看链接。默认情况下，当 Radius 认证配置时，Pi 使用 Radius 工件；否则，使用私有 GitHub gist。将 [`sessionShareDestination`](settings.md#sessions-and-context) 设置为 `gist` 或 `radius` 以强制指定一个目的地。

首先审查导出的或分享的会话。它们可能包含提示词、模型响应、工具参数、命令输出、文件内容和扩展消息。

## 报告错误

运行 `/bug [描述]` 可为 Pi 开发者准备一份私人报告。您可以包含会话记录、省略它，或让当前模型总结问题。请审阅任何记录或生成的摘要，因为它可能包含敏感对话数据。

报告包含环境和提供商配置（不含凭据值），以及记录的错误诊断信息。通过 `radius.pi.dev` 上传，或将同一报告导出为 zip 文件自行检查与分享。上传无需登录；Radius 身份验证会将报告归属到您的账户，以便开发者跟进。如果上传失败，Pi 会提供导出 zip 的选项。
