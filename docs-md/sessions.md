# 会话与上下文

Pi 将对话保存为会话。该会话的活动分支为下一个模型请求提供对话历史。使用会话命令可以继续工作、探索其他分支，或减少发送给模型的历史记录量。

## 继续或切换会话

Pi 会自动保存会话，除非你使用 `--no-session` 启动它。

```bash
pi --continue
pi --resume
```

`--continue` 打开当前目录的最近会话。`--resume` 打开会话选择器。在交互模式下，`/resume` 打开相同的选择器，`/new` 开始一个新会话。

每个会话记录其创建时的工作目录，并且永远不会更改。Pi 在其工作目录中运行会话，因此工具、`@path` 引用、项目配置和上下文文件都从那里解析。

| 入口点 | 工作目录 |
|---|---|
| `--continue` | 当前目录 |
| `--resume`、`/resume`、`--session`、`/import` | 会话的工作目录，可能与当前目录不同 |
| `--fork`，或从另一个目录中选择要分叉的 `--session` ID | 当前目录，在新会话中 |

如果会话的工作目录不再存在，交互模式会提供在当前目录中运行会话的选项。Pi 不会存储该选择，因此下次打开会话时会再次询问。其他模式则以错误退出。

使用 `/name` 或 `--name` 分配一个可识别的会话名称。运行 `/session` 以验证当前会话文件、ID、消息数量、token 用量和成本。

会话选择器允许你搜索、重命名和删除会话。它还可以显示路径、更改排序，并将结果限制为命名会话。有关其快捷键，请参阅 [键位绑定](keybindings.md#sessions)。

## 如何选择分支

Pi 将条目存储为树结构，因此返回到较早的点不会擦除你离开的分支。

| 操作 | 结果 | 使用时机 |
|---|---|---|
| `/tree` | 在当前会话文件内移动 | 相关的备选方案应保持在一起 |
| `/fork` | 从较早的用户消息创建新会话 | 备选方案应成为独立的工作 |
| `/clone` | 将活动分支复制到新会话 | 需要当前状态的单独副本 |

在 `/tree` 中，选择一条用户消息以将其文本放回编辑器。编辑并提交以创建另一个分支。选择助手回复或其他条目则在该条目之后继续，编辑器为空。

当你离开一个分支时，Pi 可以总结该分支并将总结附加到你进入的分支。这保留了被放弃路径的相关工作，而无需包含其中的每一条消息。

关于持久化的树和条目类型，请参阅 [会话格式](/docs/session-format/)。

## 管理对话上下文

模型接收的是活动分支，而非会话文件中的所有分支。Pi会将历史记录与系统提示、发现的上下文文件、可用工具及加载的技能描述结合起来。[Pi的工作原理](how-pi-works.md#context)一节描述了这些输入是如何被整合的。

页脚会显示当前的上下文使用情况。当活动上下文接近模型的限制时，Pi通常会自动压缩较旧的历史记录。压缩操作会添加摘要并保留最近的消息，但不会删除原始的会话条目。

运行 `/compact` 可手动进行压缩。若希望摘要保留特定主题或决策，可添加相应指令。通过[设置](settings.md#compaction)可配置自动压缩及保留的历史记录。

如果提供商不可用或无法接受摘要请求，压缩可能会失败。解决提供商问题后，再次运行 `/compact`。禁用自动压缩并不会禁用手动命令。

有关阈值、保留边界、分支摘要行为及扩展钩子的详细信息，请参阅[压缩参考](/docs/compaction/)。

## 控制会话存储

默认情况下，Pi 将会话存储在 `~/.pi/agent/sessions/` 下，按工作目录分组。使用 `--session-dir`、`PI_CODING_AGENT_SESSION_DIR` 或 `sessionDir` 设置来选择其他位置。CLI 选项具有最高优先级。

使用 `--no-session` 进行临时运行。临时会话在 Pi 退出后无法恢复。

## 导出或共享会话

使用 `/export` 将当前会话写入为 HTML 或 JSONL。使用 `/share` 上传它并获得查看链接。默认情况下，当配置了 Radius 认证时，Pi 使用 Radius 工件；否则，它使用私有的 GitHub gist。将 [`sessionShareDestination`](settings.md#sessions-and-context) 设置为 `gist` 或 `radius` 以强制指定一个目标。

请先审查导出的或共享的会话。它们可能包含提示词、模型响应、工具参数、命令输出、文件内容和扩展消息。

## 报告 Bug

运行 `/bug [描述]` 可为 Pi 开发者准备一份私密报告。你可以包含会话转录、省略它，或要求当前模型总结问题。请审阅任何转录或生成的摘要，因为它可能包含敏感对话数据。

报告包含环境和提供商配置（不含凭证值）以及记录的错误诊断信息。通过 `radius.pi.dev` 上传，或将同一报告导出为 zip 自行检查并分享。上传无需登录；Radius 身份验证会将报告归属到你的账户，以便开发者跟进。如果上传失败，Pi 会提供导出 zip 的选项。
