# 会话与上下文

Pi 将会话保存为一种会话形式。该会话的活动分支为下一个模型请求提供对话历史。使用会话命令来继续工作、探索其他分支，或减少发送给模型的历史信息量。

## 继续或切换会话

Pi 会自动保存会话，除非你使用 `--no-session` 启动它。

```bash
pi --continue
pi --resume
```

`--continue` 会打开当前工作目录最近一次的会话。`--resume` 会打开会话选择器。在交互模式下，`/resume` 打开同一个选择器，`/new` 则开始一个新会话。

使用 `/name` 或 `--name` 为会话指定一个可识别的名称。运行 `/session` 可查看当前会话文件、ID、消息数、令牌用量和成本。

会话选择器让你可以搜索、重命名和删除会话。它还可以显示路径、更改排序方式，并将结果限制为已命名的会话。有关快捷键，请参阅[快捷键](keybindings.md#sessions)。

## 如何分支

Pi 以树形结构存储条目，因此返回到较早的点并不会抹掉你离开的分支。

| 操作 | 结果 | 使用场景 |
|---|---|---|
| `/tree` | 在当前会话文件内移动 | 相关备选方案应保持在一起 |
| `/fork` | 从较早的用户消息创建新会话 | 备选方案应成为独立的工作 |
| `/clone` | 将活动分支复制到新会话 | 你需要当前状态的独立副本 |

在 `/tree` 中，选择一条用户消息将其文本放回编辑器。编辑并提交以创建另一个分支。选择一条助手回复或其他条目将在该条目之后继续，编辑器为空。

当你离开一个分支时，Pi 可以对其进行总结，并将该总结附到你进入的分支上。这样既保留了废弃路径中的相关工作，而不包含其中的每条消息。

有关持久化树和条目类型，请参阅[会话格式](/docs/session-format/)。

## 管理会话上下文

模型接收的是活动分支，而非会话文件中的每个分支。Pi 将该历史与系统提示、发现的上下文文件、可用工具及加载的技能描述相结合。[Pi 的工作原理](how-pi-works.md#context)描述了这些输入是如何组合的。

页脚显示当前上下文使用情况。当活动上下文接近模型限制时，Pi 通常会自动压缩较旧的历史记录。压缩会添加摘要并保留最近的消息，但不会删除原始会话条目。

运行 `/compact` 可手动压缩。当摘要需保留特定主题或决策时，您可以添加指令。通过[设置](settings.md#compaction)配置自动压缩和保留的历史记录。

如果提供商不可用或无法接受摘要请求，压缩可能失败。请解决提供商问题后重新运行 `/compact`。禁用自动压缩不会禁用手动命令。

参见[压缩参考](/docs/compaction/)了解阈值、保留边界、分支摘要行为及扩展钩子。

## 控制会话存储

默认情况下，Pi 将会话存储在 `~/.pi/agent/sessions/` 下，按工作目录分组。使用 `--session-dir`、`PI_CODING_AGENT_SESSION_DIR` 或 `sessionDir` 设置来选择其他位置。命令行选项优先级最高。

使用 `--no-session` 进行临时运行。临时会话在 Pi 退出后无法恢复。

当您已经知道会话路径或 ID 时使用 `--session`。在交互模式开始前，使用 `--fork` 从现有会话创建新会话。

## 导出或分享会话

使用 `/export` 将当前会话导出为 HTML 或 JSONL 格式。使用 `/share` 上传会话并获取查看链接。当配置了 Radius 认证时，Pi 使用 Radius 工件；否则，使用私有 GitHub gist。

请先审查导出的或分享的会话。它们可能包含提示词、模型响应、工具参数、命令输出、文件内容以及扩展消息。

## 报告Bug

运行 `/bug [描述]` 可为 Pi 开发者准备一份私密报告。你可以附上会话记录、省略该记录，或让当前模型对问题进行总结。鉴于会话记录或生成的总结可能包含敏感对话数据，请务必审阅。

报告包含环境与提供商配置（不含凭证值）以及记录的错误诊断信息。你可通过 `radius.pi.dev` 上传，或将报告导出为zip压缩包自行查看和分享。上传无需登录；Radius 认证会将报告归属于你的账户，以便开发者跟进。若上传失败，Pi 会提供导出 zip 的选项。
