# 提示词模板

提示词模板将 Markdown 文件转化为可复用的 `/` 命令。当您希望复用相同的提示词，而无需添加可执行行为或大量辅助说明时，可使用此功能。

模板可接受参数，并出现在命令补全中。Pi 可从个人配置、项目配置、显式路径或 Pi 软件包中加载模板。项目配置仅在授予项目信任后加载。

## 创建模板

创建 `~/.pi/agent/prompts/review.md`：

```markdown
---
description: 审查暂存的 git 更改
argument-hint: "[focus]"
---
审查暂存的更改。重点关注 ${1:-正确性、安全性和错误处理}。
```

文件名即命令名，因此该模板可作为 `/review` 使用。`description` 会出现在命令补全中。若省略，Pi 将使用首个非空行。

`argument-hint` 为可选项。必需参数请使用 `<尖括号>`，可选参数请使用 `[方括号]`。

在活动会话中添加或更改模板后，请运行 `/reload`。

<a id="invoke-a-template"></a>

## 使用模板

在编辑器中输入模板命令：

```text
/review
/review concurrency
```

Pi 会在生成文本进入代理之前展开模板。扩展首先通过 `input` 事件接收原始输入，除非有同名扩展命令处理它。

模板支持以下替换：

| 语法 | 结果 |
|---|---|
| `$1`, `$2`, … | 一个位置参数 |
| `$@` 或 `$ARGUMENTS` | 所有参数以空格连接 |
| `${1:-default}` | 第一个参数，或默认值 |
| `${@:-default}` | 所有参数，或默认值 |
| `${@:N}` | 从位置 `N` 开始的参数 |
| `${@:N:L}` | 从位置 `N` 开始的 `L` 个参数 |

参数遵循类 shell 的引号规则，因此 `/review "API compatibility"` 提供一个包含空格的参数。

<a id="choose-where-it-loads"></a>

## 将其添加到 Pi

将模板放在您的用户或项目提示词目录中。常规提示词目录仅加载直接的 `.md` 子文件。

设置和软件包可以选择嵌套的 Markdown 文件；软件包清单可以使用显式路径和通配符来缩小发现范围。有关这些选项，请参阅 [设置](settings.md#resources) 和 [Pi 软件包](/docs/packages/)。

授予信任后，项目模板会成为编辑器中的命令。在信任陌生的项目之前，请审查其内容。请参阅 [安全](security.md#understand-project-trust)。
