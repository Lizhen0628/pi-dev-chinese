# Pi 的工作原理

Pi 协调模型请求、工具执行、上下文组装和会话存储。会话是 Pi 对对话的记录，包括消息、工具调用及结果、模型变更、压缩及其他事件。

会话中的消息和事件构成一棵树。树中的每条路径都是一个分支。以当前条目结尾的分支是活动分支，并为下一个模型请求提供历史记录。

## 智能体循环

提交的消息会被添加到活动分支。Pi 基于系统提示、活动分支、可用工具和模型设置构建模型请求，然后通过选定的提供商发送。

提供商流式返回助理响应，其中可包含文本和工具调用。Pi 记录响应、执行每个工具调用并记录结果，从而完成一轮。若工具结果或排队消息需要另一次模型请求，Pi 将开始新一轮；否则，运行结束。

引导消息在当前助理轮次之后进入。追问消息在智能体完成待处理工作后进入。中止会停止当前运行，并将排队消息返回给编辑器。

## 上下文

活动分支提供对话历史。Pi 将其会话条目转换为模型兼容的用户、助手和工具结果消息。

Pi 根据其基础指令和发现的上下文文件构建系统提示。请求还携带工具定义和技能描述。

完整的技能指令按需加载。扩展可以添加指令或转换上下文。

提示词模板在编辑器输入成为用户消息之前对其进行扩展。选中的文件、图像、粘贴的文本和 shell 输出可以成为消息内容。

## 会话

持久化会话为 JSONL 文件。每个树条目都有一个 ID，并指向其父条目。当前条目标识活动分支。

从较早的条目继续会在同一文件中创建另一个分支。分叉和克隆会将选定的历史记录复制到新的会话文件中。

模型上下文从活动分支重建。压缩会插入一个摘要条目，在后续模型请求中替换较旧的消息。原始条目保留在会话树中。

## 接口

交互模式在终端中渲染会话和代理事件。打印模式运行一个提示词并写入最终响应。JSON模式将代理事件以JSONL格式写入。

RPC模式在标准输入上接受JSONL命令，并将响应和事件写入标准输出。TypeScript SDK在进程内创建和控制代理会话。

所有接口使用相同的代理和会话机制。

## 扩展与资源

扩展是加载到 Pi 进程中的 TypeScript 模块。其工厂函数注册工具、命令、快捷键、提供商、事件处理器、渲染器及终端界面。

技能提供按需指令及支持文件。提示词模板提供可复用的消息文本。主题提供终端配色。Pi 软件包通过 npm 或 git 分发这些资源。

## 信任与权限

Pi 在加载项目设置和资源之前，会先进行项目信任判定。完成信任判定并加载项目资源后，Pi 再加载上下文文件。启用的工具使用 Pi 进程的操作系统权限。扩展在该进程内部执行。
